# Roadmap

FAFipedia is a derived, agent-optimized layer over the canonical FAF spec.
The roadmap is incremental, always-shippable, zero-tension. No promised
dates — items land when they're ready.

## Migration from `Wolfe-Jam/faf-agent`

FAFipedia previously lived as two files inside the `faf-agent` private MCP
server (`fafipedia.fafi` + `substrate.fafi`), mirrored to
`faf-agent-public` for FAFA's consumption. The dedicated repo lifts that
out for first-class public visibility.

- [x] **Step 1** — Repo created (`Wolfe-Jam/fafipedia`, public, MIT)
- [x] **Step 2** — Copy `fafipedia.fafi` + `substrate.fafi` + validation
      tooling + README + `project.faf` + `docs/README.fafa`
- [ ] **Step 3** — Swap `FAFIPEDIA_URL` + `SUBSTRATE_BUNDLE_URL` in
      `FAF-Voice/direct-xai/api/grok-agent.js` to read from this repo
- [ ] **Step 4** — Extend the `faf-agent` `#16` mirror to dual-write
      (or retire it once source-of-truth moves here)
- [ ] **Step 5** — Retire the copies in `faf-agent` once source-of-truth
      is verified here

## Post-migration

- [ ] `.faf-dna` — generated by `bunx faf init` (not hand-authored; the
      file is a tool artifact, faking it would be a forgery)
- [ ] `CLAUDE.md` / `GROK.md` — per-AI context dialects (deferred to
      wolfejam / Grok voice)
- [ ] **Build-script reconciliation** — the `build-substrate-bundle.mjs`
      pipeline currently lives in `FAF-Voice/direct-xai/scripts/` and is
      tightly coupled to `grok-agent.js` (shared `extractSections`,
      `proseStrong`, `extractIntro`). Moving the pipeline here requires
      extracting those functions to a shared module.
- [ ] **Five-file split** — `core.fafi`, `stack.fafi`, `mcp.fafi`,
      `agent.fafi`, `performance.fafi`. Pulled forward when the corpus
      warrants; pre-mature now (35 entries fit comfortably in one file).
- [ ] **`docs/faf_index.fafi`** — currently inline in `fafipedia.fafi`
      as a generated `Index`-type entry. Extracting to its own file
      lands when the build-script reconciliation does.

## Future

The architecture is `dogfood of a mirrored-expert-agent-on-FAF pattern`
(see `fafipedia-is-dogfood-of-mirrored-expert-platform` doctrine). A
second instance (a different domain — KOPipedia, F1, etc.) would be
**pulled**, not pushed.
